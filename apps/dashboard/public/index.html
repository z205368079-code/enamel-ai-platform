DeepSeek 受控兜底机制

精准触发规则
  • 触发条件：仅当 MaxKB 知识库检索并返回精确 NO_ANSWER 标识，且网关配置了 DEEPSEEK_API_KEY 时，才调用 DeepSeek 作为通用大模型兜底。
  • 非触发场景：若 MaxKB 产生网络超时、HTTP 报错或响应异常，网关绝不盲目调用大模型编造答案，而是受控转入人工。
  • 审计留痕：DeepSeek 的成功回答作为独立 AI Run 记录留存，避免与知识库检索结果混淆。
👨‍💼

受控 Human Handoff 人工接管

风控与状态机
  • 触发规则：客户明确要求人工（如“人工”、“投诉”）、命中 Demo 敏感风控词（赔偿、法律、人身伤害等），或连续 AI 失败超过阈值。
  • 原子状态机：在 PostgreSQL 中原子落盘状态切换（AI → HUMAN）并记录 handoff_events。
  • 第三方标记：通过 Chatwoot 官方标签 API 在保留原标签基础上追加 human_handoff，由 Chatwoot 人工坐席继续跟进，网关不再自动应答。
🏛️

系统职责与源码边界

非侵入式集成
  • 第三方组件：Chatwoot 与 MaxKB 为独立外部服务，本项目不 fork、不魔改、不复制代码，全部通过标准 HTTP API 进行非侵入式解耦交互。
  • 自主实现边界：AI Gateway（Node.js/TypeScript）、状态机、幂等认领、审计流转、BFF 及本运营控制台为本项目完全自主研发。
  • 安全防环：网关仅消费 incoming 客户消息，忽略自己发出的 outgoing 消息，从根源杜绝消息循环。
🛡️

Dashboard 前端与 BFF 安全隔离

凭据零泄露
  • Token 隔离：网关 /internal/* 接口受 INTERNAL_API_TOKEN 保护，该 Token 仅驻留在 Dashboard BFF 服务端内存中。
  • 前端安全：浏览器仅能访问 BFF 提供的无认证只读 /api/* 接口，静态文件、Bundle、URL 及前端日志中绝对不存在任何敏感密钥。
  • 最小化只读：当前控制台严格维持只读状态，不提供破坏性操作或替代 Chatwoot 坐席的越权入口。
